# TacTech i18n (Internationalization)

Production multi-language support for **TacTech Trainer iOS**.

## Languages (v1)

| Code | Language | RTL |
|------|----------|-----|
| `en` | English (source) | No |
| `es` | Español | No |
| `ar` | العربية | **Yes** |
| `zh-Hans` | 简体中文 | No |
| `fr` | Français | No |
| `hi` | हिन्दी | No |

Default for new installs: **device locale if supported, else `en`**.

Legacy AppStorage migration: `us`/`uk`/`jp`/`it`/`ru` → `en`; `cn` → `zh-Hans`; `ar` → `ar`.

## Architecture

- **String Catalog:** `TacTech/Resources/Localizable.xcstrings` (source `en` + 5 locales).
- **Runtime override:** `LocalizationController` + `AppLanguage`.
- **Root wiring:** `TacTechApp` → `.ttAppLocalization()` sets:
  - `environment(\.locale, …)`
  - `environment(\.layoutDirection, …)` (RTL for Arabic)
  - `id(revision)` so the tree rebuilds on change
- **Persistence:** `settings.languageCode` (BCP-47) + `settings.language` (native label).
- **Server sync:** `GET/PUT /me/preferences/language` (`languageCode`, `bilingual: false`). Soft-fail offline.

## How to add a string

1. Add the key to `Localizable.xcstrings` (Xcode String Catalog editor) with English value.
2. Fill `es`, `ar`, `zh-Hans`, `fr`, `hi` (or mark **Needs Review** — never leave empty).
3. In SwiftUI use:
   - `Text("my.key")` / `Text(String(localized: "my.key"))`, or
   - `String(localized: "my.key", locale: LocalizationController.shared.locale)` when outside environment locale.
4. Prefer catalog **plurals** / substitutions over concatenating translated fragments.
5. Localize `accessibilityLabel` / hints too.

> All user-facing strings must use the String Catalog. Raw `"Hardcoded"` in Views is a bug unless `#Preview` only.

## Formatting

| Use | Rule |
|-----|------|
| API wire dates (`yyyy-MM-dd`) | Keep `en_US_POSIX` |
| UI dates / numbers / relative time | `FormatStyle` / locale from `LocalizationController` |
| Backend error `detail` | Show as-is until server localizes; optional mapped fallback by code |

## New feature PR checklist

- [ ] New UI strings in String Catalog
- [ ] Translations for `es`, `ar`, `zh-Hans`, `fr`, `hi` (or Needs Review)
- [ ] RTL checked for custom layouts (Arabic)
- [ ] Dates/numbers locale-aware for UI
- [ ] Plurals use catalog plural rules
- [ ] No English-only `count == 1 ? …` for user-facing copy

## QA (per language)

1. Select language in Settings → tabs / settings / toasts update immediately.
2. Relaunch → selection persists.
3. Arabic → RTL (back chevrons, trailing menus, sheets).
4. Auth + Find Coaches + Workout + Chat still function.
5. API date queries still use POSIX.

## Coverage notes (v1)

**Fully wired for language switch:** Language Settings, Notification Settings chrome, tab accessibility labels, Account Settings Language row, coach review CTAs, key soft toasts (join / plan / roster), home header date format, root locale/RTL.

**Still English until catalog sweep continues:** Deep Auth copy, many Trainer/Trainee feature screens, chat bubble chrome, Boost/AI paywall marketing, Help FAQ bodies. Add keys as those screens are touched — the pipeline already follows the selected language automatically.
